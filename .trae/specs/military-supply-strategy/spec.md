# 军需—主城配给—押运—载具军团—踪迹 · 体系设计总纲

> 状态：设计稿（待策划拍板）· 2026-11-08

## 1. 体系目标

把「主城配给 → 生产/锻造 → 领取押运 → 载具军团 → 小路遭遇 → 大地图指挥 → 战前计划/介入 → 城池内政」串成**一条可玩的资源—军事闭环**，并与现有任务/触发器/命令体系严格对齐：

```
生产（工坊/伐木/铁匠/锻造）
   ↓ 产出物资与装备
主城库存（按等级共享额度）
   ↓ 领取（进背包） / 押运（进寨子仓库）
押运队伍（载具 + 护卫）
   ↓ 小路上的遭遇战（可介入）
军团（编制/主将/副将/兵种/策略/阵法）
   ↓ 大地图行军、警戒、痕迹、目标方向
战前计划 → 战斗执行 → 玩家介入 → 战果结算
   ↓
城镇归属与内政（产出/税收/兵源/忠诚）→ 反哺生产与配给
```

## 2. 需求原文汇总（语义不删减）

### 2.1 第一轮：军需生产 / 配给 / 押运 / 载具

- 建筑物：工坊、伐木做弓箭、铁匠修复武器装备。
- 主城才有物资供应；主城物资按人按等级共享；需要领取、押运才能进自己寨子、进自己口袋；押运途中可能被抢。
- 主城部队（特殊载具）：行军、战斗、扎营（防御 +50%、攻击 +50%）、拔营。
- 逃跑、上车；放入载具，通过一条小路，路上会打杀一些生物；载具也可以操作。
- 载具指令：跟随、冲锋、原地防御、逃跑。
- 踪迹、消灭踪迹。

### 2.2 第二轮：军团 / 城镇 / 战前计划

- 军团相关：与 NPC 对话「花费 xx 铜钱，招募 xx 人」；拥有军团、组建军团、解散军团；大地图上选择军团并下达军团指令（进攻、防守、运输、移动、扎营、布阵）；小队指令（跟随、进攻、防守、冲锋、撤退）；设置主将、设置副将。
- 城镇：拥有城镇；城镇/城池/村落的内政；城镇有「攻击」「输送」选项。
- 战前计划 → 执行战斗：通过对军队的前期计划来执行战斗。兵种：刀盾兵、枪兵、弓箭兵；轻骑兵、重骑兵、弓骑兵。策略：移动、进攻、防守、扎营、行军、急行军、布阵。
- 设计补充：军团与现有 SceneArmyCommandFlow / army column 怎么对接；兵种与策略做成数据表；"战前计划→执行"给出最小形态（计划即参数 vs 即时战术层）；内政最小闭环；招募/组建/解散/指令必须走任务与命令体系。

### 2.3 第三轮：大地图指挥与改造方案

- 大地图上控制军团：可设置军团作战目标与方向。
- 直观看到：可供行军的通路、军队警戒范围、军队移动后留下的路线痕迹（参考骑马与砍杀观感）。
- 大地图上也能控制城池，设置城池目标方向。
- 可以获取军团直接控制权（从战略层切到操作层，操纵主将与部队）。
- 交付要求：至少三条改造路线（最小改造 / 战略层实体+时间推进 / 战略层+可切入战术双层）；通路/警戒/痕迹的取舍建议；城池目标方向数据与 UI；接管军团切换路径；教程设计；补齐拍板问题。

### 2.4 第四轮：生产链细化 / 阵法 / 玩家介入

- 武器与装备锻造：与铁匠修复、工坊/伐木做弓箭同一条生产链；说明输入材料、产出品质/词条、失败与损耗、与铜钱经济关系；装备属性从哪来、是否新增词条系统、如何对接现有装备/背包。
- 阵法：利用地势与建筑物（高地、隘口、河流、桥梁；寨墙、箭塔）的阵法；利用军队战斗的阵法（锋矢、鹤翼、方圆、鱼鳞等）与兵种匹配、克制与惩罚；用数据表表达，编辑器怎么配；与「移动/进攻/防守/扎营/行军/急行军/布阵」统一口径，不允许两套阵法概念。
- 玩家介入军队战斗：介入形式（亲自上阵、下达指令、关键时刻战术选择）、时机窗口与代价；"介入 → 结果改善"的反馈链条（战报、士气变化、局部战线推进）；最小可玩形态与后续扩展；与现有「抽象战果」和「实时战场」两条链分别怎么接。

## 3. 全局分层（v2 修订：两层级，2026-11-09 用户裁定）

```
层级一：自动化指令（战略层）
  武装单位 = 军团 / 城池 / 关卡 / 军营（NPC 兵力，统一 armyStates 表）
  玩家下大方向指令：进攻 / 防守 / 运输 / 移动 / 扎营（五条战略指令）
  战前部署（两处入口）：①大地图设默认值（兵种构成 / 军团阵型 / 主将位置）②进战场**接战前**（`PRE_BATTLE`）可临时调整 + 勾选设为默认——**接战即锁死不可改**
  → 自动执行循环接管：编队、寻路、接战、结算、入档，玩家可离场
       ↕ 玩家恰在战场场景 → 实体展开（「在场即介入」）；三种入场身份：接管/支援/旁观
         战中仅「接管」身份可下将令（姿态切换 / 集火 / 撤退），部署类一律锁死
层级二：随行小队（战术层，ARPG 陪伴）
  玩家身边的将领/士兵 NPC（亲卫队 0~100 实体，上限由统率+官职决定；另统兵 ≤10000 抽象兵力，阵亡自动从兵源补位；无分队）
  玩家只切五档：跟随 / 进攻 / 防守 / 冲锋 / 撤退
  玩家战斗倒地 → 背包随机掉 1~3 件装备/材料（零损耗，可被敌 NPC 拾取夺回），已穿戴不掉；剧情倒地豁免
       ↕
战斗层   A. 抽象战果（roster + 兵种/地势修正，玩家不在场；主将按数值参与，不展开实体）
         B. 实时战斗（玩家在场，随行队协同；**主将一律下场**，位置由战前部署控制）——无模式选择 UI
       ↕
操作层（ARPG）  玩家主角直接操控（场景现有玩法）
```

> v1 的「战略层↕接管↕军团层」四层模型作废：无 v1 那种「玩家替身去接管 NPC 军团」的切换层（玩家永远 ARPG 主角）——注意与 v4 的「**接管**」区分：v4 接管是**战斗内的指挥权归属**（拿将令权），不是切换主角模型；无五军编组选择、无介入窗口；**阵法保留为玩家可设置的数值修正预设**（v2.1 二次裁定 2026-11-09，布阵 = 设置阵法，归战前部署；**v2.3 第六次拍板：阵型只给三类信息——数值修正 / 适用场景标签 / 地形偏好，无克制、无两两强弱标签**）。**v2.2/v2.3（2026-11-09 第五/六次拍板）**：主将一律下场（位置由战前部署控制）+ 战前部署**两处入口**（大地图默认 / 战场接战前临时调整）且**接战即锁**+ 战中仅接管身份可将令（详见 [模块 5](05-formation-terrain.md) §6.3、[模块 6](06-battle-plan-intervene.md) §3.6/§3.7）。**v2.4（第七次拍板）**：部署调整判据只留 `battle.status === 'PRE_BATTLE'`（不看入场身份）、卖价上限放宽至 ×3、三种身份之一「参战」改名「接管」。修订明细见 [模块 3 v2](03-army-squads.md) §0 与 §10。

**单一事实源原则**（强制）：

| 事实类型 | 权威落点 | 只读镜像 |
|---|---|---|
| 库存/材料/装备 | `InventoryComponent` + `InventoryTransactionService` | UI 快照 |
| 建筑/生产进度 | 生产/建造 System（`captureRuntime`） | placement 表现 |
| 城池归属/资源/民心 | `blackboard.cityStates`（事实 → checkpoint） | 大地图/内政 UI |
| 军团编制/位置/目标 | 战略层军团实体（新增） + `storyState`/checkpoint | 大地图标记 |
| 剧情推进/首件/解锁 | `state.transaction` 事实 | 任务步骤 |

**禁止旁路**：任何生产、领取、押运、招募、组建、指令、内政操作，都必须由 UI → command → System → `state.transaction`/checkpoint 提交；UI 不直接改库存与状态。

## 5. 全局工程约束

1. **任务系统承载**：所有玩法节点通过 `quests.json` / `triggers.json` / `commands.json` 编排；缺的能力先补 Objective 类型或 Command，不允许在场景 Flow 里写一次性分支。
2. **数据驱动**：兵种、策略、阵法、配方、城池产出、载具参数、招募成本全部进内容库/项目配置，编辑器可编；禁止硬编码在 UI 或场景流。
3. **存档**：持续存在的实体（军团/押运队/建筑/生产队列/城池）必须 `capture/restore`；一次性剧情事实走 `state.transaction`。
4. **零回归**：S01～S14 现有剧情、建造、战斗、搬运、载具链路行为不变；新能力以开关/新数据键渐进接入。
5. **三端输入**：PC（鼠标键盘）/手柄/触屏的入口在模块内单列，且必须与现有 `InputHints` 提示体系一致。
6. **不碰性能线**：不修改 `after-scene-phase-longframe` 相关文件与其在跑改动。
