## 0. 结论摘要

1. **前半段玩家操控张角**：村口择人 → 烧符投锅盛粥递碗 → 缠铜钱 → 听罪状 → 认罪 → **⑨ 起事**（张角 + 20 黄巾 vs 县尉 **100 兵单波**，张角阵亡即结局）。
2. **⑨ 结束操控权回到玩家（年轻人）**——不再是全程张角。
3. **新增分叉**：张角邀请加入黄巾军，**加入 / 暂时还不行**；两条线**最终都会继承张角势力**，分叉**只影响体验、编制与少量奖励**，不加惩罚性结局、不改主线流程与敌人总量。
4. **两条支线各自招兵**：加入 → 80 黄巾军（张角阵营，围剿时**切回张角**操盘）；不加入 → 亲卫（**初始 10，上限由玩家统率与官职决定**，玩家阵营，围剿时**可选是否以援军参战，不能操控张角**）。
5. **围剿规模为傅燮率一千人**：总兵力 **1000（单波）**，**同屏上限 100**，其余按**占位补员**（死一个补一个）进场；**击破 500 后傅燮登场，斩将即溃散**；扎营完成 `campComplete` 触发，姿态教程挂在此段。
6. **主线前提**：两种选择**最终都会继承张角势力**，主线目标是**一统黄河中下游平原**——所以分叉**不改变主线走向**，只影响体验与少量奖励，**后期由玩家自行调整**；不写难度标记、不做成就，阵营分叉只认 `alignment`。

## 1. 核心设定与法理前提（不变）

| 项 | 设定 |
|---|---|
| **符水** | **加了烧了一部分的符纸的粥**。官府叫法：「妖言惑众」 |
| **铜钱剑** | **七枚铜钱缠成剑形**。官府叫法：「私铸兵刃」 |
| **法律前提** | **赈济是官府专营**。个人施粥、发钱＝僭越官府职权＝"聚众"＝"收买人心" |
| **名字的对称** | 张角不能叫它"粥"（叫粥就违法），所以烧一部分符纸叫"符水"|
| **罪名性质** | 事实成立、定性加重：越权赈济 → 聚众（二百余口）→ 收买人心 → 私铸兵刃 → 拒捕/起事 → 图谋不轨 |
| **官兵立场** | 查禁有法理依据；台词只说"越制/聚众/妖言/私铸"，"造反"是 ⑨ 之后才被定性上去的 |

## 2. 视角与操控权（本版核心）

| 阶段 | 主控实体 | 切换方式 |
|---|---|---|
| ① 村口倒下 | 年轻人 | 既有 |
| ②~⑨ 起事前半 | **张角** | 场景装配时把玩家主控绑定为张角（**不是 `army.possess`**） |
| ⑨ 起事战斗 | **张角**（带 20 黄巾军） | 不切换 |
| **⑨ 打完** | **年轻人** | 战斗结束 → 交回主控（`army.possess.release` 或等价主控解绑）；写 `story.s02.control.returned` |
| 分叉 / 招兵 / 整备 / 扎营 | **年轻人** | 不切换 |
| 围剿（**加入**支线） | **张角** | 围剿开始 → 切回张角（`army.possess` 接管张角军团） |
| 围剿（**不加入**支线） | **年轻人** | 保持主控；可**选择**以援军身份入场（不可操控张角） |
| 战后 / 驰援交代 | **年轻人** | 不切换 |

- **年轻人是 NPC**：①~③ 躺着重伤；④~⑨ 清醒但虚弱，站在旁边看着（不参战、不施粥发钱）；
  **⑨ 之后才成为玩家操控角色**（此前一直是张角）。
- **张角不是"另一个玩家"**：⑨ 之前与围剿（加入线）时是玩家化身；其余时间是 NPC/军团主将。

## 4. 两条支线（分叉）

### 4.0 分叉的性质：体验与奖励差异（不设难度）

**主线前提**：两种选择**最终都会继承张角势力**，主线目标是**一统黄河中下游平原**。
所以分叉**不改变主线走向**，只在**编制、可操控对象、援军与战后奖励物品**上有差别，**后期由玩家自行调整**。
**本方案不设难度系统**：不写难度标记、不做成就；分叉**只认 `alignment`**。

**边界**：只改我方体验侧条件；**不改主线流程、不改敌人总量与敌人 AI/数值**
（⑨ 县尉 100 兵单波、围剿总 1000/同屏 100/补员/斩将 全部一致）。因此两分支**不需要两套关卡**，
只有互斥的刷兵组与少量数值差异。

#### 4.0.1 体验与奖励差异表（逐项）

| 维度 | 加入黄巾 | 暂时还不行 |
|---|---|---|
| 我方兵力 | 张角 + **80 黄巾** + **张角亲卫（全员实兵上场）** | 年轻人 + **亲卫**（初始 10，上限 `10 + floor(command/10) + rankBonus`，最多 80，**全员实兵上场**） |
| 我方同屏 | **全部上场**（按实际人数，不设编组代表制、不设预备队） | **全部上场**（主角 + 亲卫按实际上限） |
| 围剿时张角 | **玩家直接操控**（全技能、可指挥黄巾） | **AI 指挥**（不可操控，协防判断保守） |
| 围剿控制权 | 切张角，必然参战 | 保持年轻人，**可选**是否以援军参战 |
| 战后给予 | 张角给：**粮 20 / 铁 10 / 伤药 3** | 只给：**粮 5 / 铁 2** |
| 声望 | 黄巾 **+20** / 汉 **−10**（同阵营，军功记黄巾） | 黄巾 **+5** / 汉 **0**（盟友，独立记账） |
| 后续任务线支援 | S03+ 战役**可请求张角援军**（每战 1 次） | **无援军**；亲卫需自行募兵/补充 |
| 张角阵亡 | 结局「出师未捷身先死」 | **不判负**：重伤退场，张角军团收尾 |
| 主角（年轻人）阵亡 | 不适用（玩家=张角） | **不结局**：亲卫溃退，张角军团收尾 |
| 兵能否带走 | **不能**（黄巾归张角） | **能**（亲卫随行 S09） |
| 阵营依据 | `alignment = yellow_turban` | `alignment = independent` |

> 说明：上表与 §4.1、§4.2 是**同一批条款**，不另立说法；数值以 §4.2 为准。

#### 4.0.2 选择前让玩家知道差别（不误导）

| 方式 | 具体 |
|---|---|
| ① 台词明示 | 张角：**「跟我走，这仗我替你扛。」** / **「你不入伙，就得自己带人守。」** |
| ② 选项副标题 | `加入黄巾（有张角军团掩护）` / `暂时还不行（只能带自己的亲卫）` |
| ③ 首次选择前的一次确认框 | 列三条差异：**我方兵力更少 / 不能操控张角 / 战后支援更少**（只写方向，不写数值） |
| ④ 不给数值 | 不在 UI 里写 80/10/20 这类数字，避免攻略化；数值只留在配置里 |

### 5.7 兵力结构、占位补员与性能口径

#### 5.7.1 兵力结构（单一兵力池）

| 项 | 数值 |
|---|---|
| 总兵力 | **1000（含傅燮）** |
| 同屏上场 | **≤100**（敌方） |
| 我方上场 | **全部实兵**（黄巾 80 + 张角亲卫 / 亲卫按上限）；**不缩减、不排队、无预备队** |
| 待入场池 | 开局 900（1000 − 场上 100） |
| **傅燮** | **开局不在场**；累计击破 **500** 时登场（一次性） |
| 结束条件 | **傅燮阵亡（斩将）** |
| 池耗尽 | 1000 全部入场仍未斩将 → 仍可继续打（场上不再补员，逐步清空） |

- **同屏 100 的性质**：这是**设计约束**（手感 / 性能 / 可读性），**不是引擎限制**——引擎同屏上限 **2000**。
  - ⑨ 的 **100** = "县尉带 100 兵"的**剧情量级**；
  - 围剿的 **100** = **同屏节奏选择**（总池仍是 1000，靠补员维持）；
  - **将来要放大规模**：只需调这两个设计值（建议单场上限不超过 200，再高可读性下降），**不需要改引擎**。
- **HUD**：`场上 100 / 总 1000`（单一计数，无阶段条）；**傅燮血条在登场后才出现**（此前不显示）。
- **胜利判定 = 斩将**（傅燮阵亡，余部溃散），**不是杀满 1000**。理由见 5.7.2。
- ⑨ 的第二波 100 兵 = 刚好填满同屏上限，**一次进满、不补员**（无池）。

#### 5.7.2 时长估算（为什么不能"杀满 1000"）

| 玩法 | 估算 |
|---|---|
| 单波 1000 池、同屏 100 | 若杀满约 **20~30 分钟**（过长） |
| 击破 500 → 傅燮登场 → 斩将 | 约 **8~10 分钟**（击破 500 约 6~8 分钟 + 斩将 1~2 分钟） |
| 若开局即可直取傅燮（无门槛） | 约 **2~3 分钟**（速通，BOSS 感弱） |

#### 5.7.3 傅燮登场与胜利条件（已拍板：击破 500 登场）

- **傅燮开局不在场**。累计击破 **500**（`ledger.defeated >= 500`，即补员池由 1000 降到 500）时**登场一次**：
  带少量护兵从阵后入场、播一句台词；**登场后即可选中、可击杀**（不需要再解保护）。
- **池的关系**：登场**不重置池**，池继续按 500 往下补员（**傅燮自带 8 名护兵、不计入 1000 池**）；
  补员规则在登场前后**完全一致**（都是死 1 补 1）。
- **斩将即溃散**：傅燮阵亡 → `pool` **立即归零、停止补员**；场上余部转 `routed`（不再攻击、向场外逃、5s 后 despawn）；
  `ledger.total` 仅作表现显示"剩余溃逃 N 人"，不参与胜负。
- **实现方式（推荐）**：放在 `raidReinforce` 的补员环里做**一次性锚点**——
  `if (!fact('story.s02.raid.boss.spawned') && ledger.defeated >= 500) { spawn(FuXie); commitFact('...boss.spawned') }`。
  理由：①补员环本来每 0.2s 就在跑，不需要新钩子；②`spawnWhen` 是"进场景/重进场景"时的静态门控，
  对"战斗中累计值"不敏感，还得额外造一个 placement 条目；③用一次性事实做幂等，重入安全。
- **不采用**：`placement spawnWhen: story.s02.raid.defeated >= 500`——该条件只在场景装配时求值，战中不会重估。

#### 5.7.4 占位补员规则（死一个补一个）

1. 每 **0.2s** 检查一次：`场上敌兵 < 100` 且 `池 > 0` → **补 1 个**（不批量、不同帧灌入）。
2. 出生点：战场**两侧入口**（不在玩家正视野内凭空出现），优先补到最近空缺阵位。
3. 敌兵阵亡 → `enemy.killed` → 池 −1 → 触发补员。
4. 池空即停补；**斩将后不再补员**；**傅燮登场前后补员规则一致**（登场不打断补员，见 5.7.3）。
5. 不加入线选"不参战"时补员照常（玩家只看 HUD 与战况）。

#### 5.7.5 性能评估（100 实体同屏）

- **引擎同屏上限 2000**；本场峰值约 = 敌方 100 + 我方全部实兵（≤ 百余人），量级约 200 上下，**远未触顶**。
- 主要开销仍是 AISystem 决策、阴影 pass、Y-sort，但在 200 量级属常规负载，不构成瓶颈。
- **以下为可选优化开关（默认关闭，不是必需项）**：杂兵简化 AI（不跑完整 aggressive 决策树 / 决策降频 0.2s）、
  杂兵关闭独立阴影（`shadowProfile: null`）、共用图集与同一实体模板、屏幕外池实体不创建。
- **我方兵力全部上场**：加入线 = 张角 + 80 黄巾 + 张角亲卫；不加入线 = 主角 + 亲卫（按实际上限）。与敌方 100 同屏并存，
  **无硬冲突**；不再做编组代表制。

#### 5.7.6 实现改造点

| 项 | 现状 | 改造 |
|---|---|---|
| `PlacementSpawner` | 支持 `spawnWhen`、运行时 `_ensureSpawnedPlacement`（S01 狼王先例）；**不支持死亡即补位** | **不改核心**；新增军团层"兵力池"数据（`ledger.total / ledger.pool`） |
| 补员控制器 | 无 | **新增** `ReinforcementController`：监听 `enemy.killed` → 池 −1 → 补 1；或复用 `_ensureSpawnedPlacement` 派生虚拟 placement |
| 胜负判定 | `waveCleared{groupId}` 以整组清空判定 | 改为**斩将**（傅燮 death）；**登场锚点读 `ledger.defeated >= 500`**（一次性事实幂等） |
| HUD | 现有血条 + 波次提示 | 新增"场上/总兵力"条（**无阶段条**）；**傅燮血条登场后出现** |

- **改造量：中**（1 个新控制器 + 1 个 HUD + 胜负判定改造），不触碰 `PlacementSpawner` 核心。
- **更省的替代（推荐做法）**：**逻辑兵与表现兵分离**——总兵力 1000 只作 `ledger` 数值，场上永远只有 ≤100 个表现实体，
  两者用补员池挂钩。**不推荐**把实体真扩到 1000（内存/AI/渲染都会崩），也不需要改造生成器的批量能力。
