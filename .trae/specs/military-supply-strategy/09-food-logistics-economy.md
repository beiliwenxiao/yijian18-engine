# 模块 9：粮草与后勤经济（粮道 / 损耗 / 断粮 / 经济体系）

> 状态：设计稿（可行性已判；13 条全部定稿，含 P16/P17 联动生效值）· 2026-11-09
> 归属：[军需—配给—押运—军团体系总纲](spec.md) 模块 9
> 需求原话映射：粮道抢夺、运输、烧毁；武器装备损耗；玩家背包粮食有限、运粮车/运输队运得多；
> 军团战斗时粮草存放在军营，没粮不能出兵、强留逃散、士气快速下降；粮草按时间消耗；
> 问可行性 + 是否要构造通缩经济体系。
> 定位：**不新增一套"粮草资源"，而是给现有 `resource.food` + 模块 2 物流 + 模块 3 军团 + 模块 7 日结
> 加一条"按日结算的消耗与惩罚"规则层**。

---

## 1. 可行性判断（结论先行）

**闭环成立，但不能按"实时逐兵消耗 + 断粮立刻逃散"裸实现。** 必须同时按下三条护栏，否则必然退化成"玩家被判死刑"的负体验：

| # | 护栏 | 一句话 |
|---|---|---|
| ① | **日结结算**，不是每帧 | 消耗/士气/逃散只在 `advanceDays` 结算一次；实时战斗内不扣粮 |
| ② | **断粮分级、可恢复、有下限** | 断粮 3 天内只掉士气不减员；逃散最低保留 30% 建制；补给到位当日止血 |
| ③ | **AI 同规则（带系数）** | 敌方军团同受粮草约束，只用"日结算术"轻量实现，不给玩家单方面豁免 |

### 1.1 五个关键风险逐条判定

| 风险 | 判定 | 护栏设计 |
|---|---|---|
| **死亡螺旋** | **真实存在，是最大风险**：逃散→战力降→打不赢→更没粮，正反馈失控 | ①逃散有**地板**（≥30% 初始兵力，建制不散）；②断粮只先扣士气、第 3 日才减员；③**散兵池**：逃散人员 30 天内可招回（`army.regroup`），不是永久蒸发；④剧情关键军团挂 `noDesertion` 白名单；⑤读档补算上限 7 天（§1.2-⑤） |
| **反复跑腿的琐碎感** | **次大风险**：如果"每天必须亲自运一趟"，玩法立刻变搬砖 | ①运量放大：一次运粮车 = 200 人日，不是几袋米；②**自动押运**：下达 `transport` 指令后无人值守（模块 2 押运队 + 模块 3 自动化）；③**驻地自动补粮**：城池→军营按日自动输送（有通路即自动），玩家只维护通路；④只在**通路被断/被烧**时才需要玩家亲自出手 → 把"重复劳动"转成"偶发危机处理" |
| **断粮惩罚是否可恢复** | **必须可恢复，否则等于删档** | 四档状态机 饱食→紧张→断粮→饥溃，**逐档可退回**；补给到位：当日停逃、士气 +5/日回升至基准；饥溃后 1 日缓冲才恢复战力（惩罚有惯性但非永久） |
| **AI 军团是否同样受约束** | **必须受，否则玩家观感崩**（"凭什么敌人不吃粮"） | 同一 `FoodLedger` 规则；AI 侧走**日结纯算术**（不展开实体），难度系数 `aiSupplyEfficiency`（默认 1.0，可调到 0.6 给简单难度）；玩家优势来自"干预"（截粮/烧粮）而非规则豁免 |
| **读档 / 离线时间怎么算** | **唯一口径 = `story.currentDay`**，不用真实时钟 | ①只按"日"结算，不按真实秒；②`supply.settledDay` 幂等标记 + 差值补算（同一 `operationId` 幂等，重复读档不双扣）；③补算上限 `maxCatchUpDays = 7`（超出按 7 天计 + warn），防"存个档放一周回来兵全跑光"；④**关闭离线惩罚**——不推进天数就不消耗 |

### 1.2 三层时间尺度（不混用）

| 尺度 | 触发 | 算什么 | 不算什么 |
|---|---|---|---|
| 实时帧 | 场景内战斗 | 什么都不算 | 粮草、士气、逃散 |
| **日结**（主） | `TimeSystem.advanceDays` | 军团日耗、士气、逃散、驻军自动补粮、城池产出（模块 7 ①②③④） | 位置、寻路 |
| 战略刻 500ms | 模块 4 `StrategicAdvanceSystem` | 行军位置、**通路/粮道被断检测**、遭遇判定 | 不做数值扣减（只发事件） |

> 关键设计：**断路检测在战略刻，扣粮在日结**。这样"粮道被断"是事件（可反应），而不是每 500ms 掉一次数。

### 1.3 一句话结论

这套玩法**值得做**，但它的乐趣点在"**偶发的后勤危机**"（粮道被截、军营被烧、断粮抉择：退回还是抢粮），**不在"每天的例行运粮"**。所以所有设计取舍都朝"把例行劳动自动化、把危机留给玩家"这一个方向收敛。

## 3. 数值骨架（参数表，不是死数字）

### 3.1 消耗速率

```
军团日耗 = Σ( 人数 × personDayFactor[兵种] )            // 单位：粮秣单位（1 单位 = 1 个 resource.food）
personDayFactor：步兵 0.8 / 弓兵 0.8 / 辎重兵 0.8 / 骑兵 2.4（含马料）
  // 基准 1 / 1 / 1 / 3，因 M1-P16（箭矢）+ P17（耐久）双开已按 ×0.8 生效（见下表与 §5.6）
```

| 参数 | 默认 | 建议区间 | 影响 | 备注 |
|---|---|---|---|---|
| `personDayFactor.melee` | **0.8** | 0.5~1.5 | 步兵日耗 | 太低则粮草无压力；**0.8 为 M1-P16/P17 双开的生效值（基准 1 × 0.8）** |
| `personDayFactor.archer` | **0.8** | 0.5~1.5 | 弓兵日耗 | 同上（箭矢已单独收费，不重复加价） |
| `personDayFactor.cavalry` | **2.4** | 2~4 | 骑兵日耗（含马料） | 基准 3 × 0.8；骑兵强但贵，仍是"粮草约束"的主杠杆 |
| `army.baseUpkeep` | 0 | 0~10 | 军团固定日耗（辎重/杂役） | 0 = 纯人头计 |
| `storageSpoilPerDay` | **0.003** | 0~0.02 | 库存自然损耗（粮草专属 sink） | 由 0.005 下调，随日耗同向收紧；与"通缩"讨论挂钩（§4） |

> **下调依据（已生效）**：M1 三条已定稿——**P16 箭矢作消耗品 = 是**、**P17 装备耐久消耗 = 是**（P18 工坊可建造 = 是）。
> 粮草不再是唯一强制消耗口，按 [m1-foundation.md §7.1](m1-foundation.md) 的联动约定 **×0.8 执行**（基准值 1 / 1 / 3 → 0.8 / 0.8 / 2.4），
> `storageSpoilPerDay` 0.005 → 0.003。**改这里必须同步 [m1-foundation.md §7.1](m1-foundation.md) 的联动表，反之亦然。**
>
> 锚点自检（按 0.8 生效值）：一支 100 人步兵团 = **80 / 日**，1 辆运粮车（`cargo 200`）可撑 **2.5 天**；
> 一个满编 1000 人军团 = **800 / 日**，需军营常备 4000+ 才能出征 5 天。**量级仍让"运粮"有存在感但不至于搬砖**。
> 若将来改判 M1-P16/P17 任一为否，按 §5.6 的对照表反向恢复（两个都不开 → 基准 ×1.2）。

### 3.2 容量梯度

| 载体 | 容量（粮秣单位） | 依据 | 设计意图 |
|---|---|---|---|
| 玩家背包 | 实用 **200~400**（24 槽，粮占 2~4 槽 × 99） | `InventoryComponent.maxSlots:24` + `maxStack:99` | **必须装不满一场战役**——逼出"车/队/军营" |

| 运粮车（大车） | **200** | 新增载具定义 | 一次运一个百人队的 **2.5 日量**（按 0.8 生效值 80/日） |
| 军营（营地仓） | **500 起，每级 +250，上限 2000** | `SceneContainerInventoryRegistry` 容器 `maxSlots` | 出征基地，容量就是"能打几天"（500 ≈ 百人队 6 日） |
| 城池粮仓 | 无上限（受产出/民心约束） | `cityStates.resources.food` | 战略储备，靠粮道运转 |

### 3.3 断粮衰减曲线（四档）

| 档位 | 判定 | 士气 | 逃散 | 其他 |
|---|---|---|---|---|
| 饱食 | 库存 ≥ 1 日耗 | — | 0 | — |
| 紧张 | 0 < 库存 < 1 日耗 | **-3 / 日** | 0 | 发 `army.supplyLow`，UI 转黄 |
| 断粮 | 库存 = 0 且缺口持续 ≤ 3 日 | **-8 / 日** | **2% / 日，逐日 +1.5%**（2/3.5/5/6.5/8 封顶） | **禁止 `attack`/`move`**（与 `starved` 同语义）；发 `army.supplyEmpty` |
| 饥溃 | 断粮 > 3 日 | **-15 / 日**（下限 0） | **8% / 日**（固定） | 战力系数 `×0.7`；发 `army.desertion` |

| 参数 | 默认 | 说明 |
|---|---|---|
| `moraleDrain.tight` | 3 / 日 | 紧张档 |
| `moraleDrain.empty` | 8 / 日 | 断粮档 |
| `moraleDrain.collapse` | 15 / 日 | 饥溃档 |
| `desertion.startDay` | 3 | 第 3 日起才减员（前 3 天只掉士气——护栏②） |
| `desertion.baseRate` | 0.02 | 起始逃散率 |
| `desertion.rateStep` | 0.015 | 每日递增 |
| `desertion.maxRate` | 0.08 | 封顶 |
| `desertion.floorRatio` | 0.30 | **兵力地板**（≥30% 初始，建制不散）——与 [模块 6](06-battle-plan-intervene.md) §5.5 `manpowerFloorRatio` **同值、独立参数、共享同一地板**：同一天先结战斗事件（战败/逃亡随机减兵）再日结饥荒逃散，任一方触地板即停（2026-11-09 第五次拍板） |
| `moraleRecoverPerDay` | 5 / 日 | 补给到位后回升速度（上限 = 基准士气） |
| `regroupWindowDays` | 30 | 散兵池可招回窗口 |
| `maxCatchUpDays` | 7 | 读档补算上限（护栏⑤） |

> `morale` 的下限效应：士气 < 30 时接战 **伤害 ×0.85、溃退阈值提前**（复用模块 5 的 `CombatModifierPipeline` 士气层，不新写战斗逻辑）。

### 3.4 烧毁（粮道/军营）

| 参数 | 默认 | 场景 |
|---|---|---|
| `razeRatio.base` | 0.60 | 常规焚粮 |
| `razeRatio.night` | 0.90 | 夜袭（无月光/火把加成） |
| `razeRatio.defended` | 0.30 | 守军在场且守方战败 |
| `razeRatio.defenderWins` | 0 | 守方胜 |
| `razeRecoverRatio` | 0.20 | 烧毁粮中可抢回比例（地面掉落 `resource.food`） |
| `razeRequiresFireSource` | `true` | 需火种/火把/火攻技能（与物品 `prop.torch`、模块 1 火把联动） |

- 烧毁的 80% **永久消失**（真消耗口，不是转移），20% 地面散落可抢回。
- **烧粮是"战略级"动作**：只能在军营/粮车这类"有存量容器"的目标上执行，不能烧玩家背包。

### 3.5 抢粮结算（复用模块 2 §3.4，不另立表）

| 场景 | 结算 |
|---|---|
| 押运队被截（战斗） | 直接套模块 2 §3.4：胜 0% / 逃 30% / 败 50% / 车毁 100%（回收 25%） |
| 粮道节点截击（无护卫/护卫战败） | 劫掠者得 **50%**，另 50% 散落原地（限时 2 日可回收） |
| 军营被攻破 | `razeRatio` 结算（守方战胜则为 0） |
| **防双扣** | 同一批粮只走一条路径：被押运表扣过的不再走 raze；军营被烧不再叠加押运损失 |

| 参数 | 默认 | 区间 | 说明 |
|---|---|---|---|
| `famineMoralePenalty.min` | 1 / 日 | 0~2 | 城池粮仓见底（< 3 日量）时民心最低衰减 |
| `famineMoralePenalty.max` | 4 / 日 | 2~8 | 完全空仓时的民心衰减 |
| `famineThresholdDays` | 3 | 1~7 | 判定"饥荒"的库存天数阈值 |
| `forage.yieldRatio` | 0.60 | 0.3~1.0 | 抢掠征得 = 当日军耗 × 该比例 |
| `forage.moraleCost` | 6 | 0~15 | 玩家阵营民心惩罚（一次性） |
| `forage.renownCost` | 3 | 0~10 | 声望惩罚（一次性） |
| `forage.alertChance` | 0.25 | 0~0.6 | 触发"附近敌军警觉 → 追兵"的概率 |

## 4. 经济体系对比：通缩 vs 受控通胀 vs 双轨分层

### 4.1 三种模式对照

| 维度 | A 纯通缩（需求方提议方向） | B 受控通胀 + 强回收口 | C 双轨/分层 |
|---|---|---|---|
| 核心手段 | 物资总量随时间净减少，钱越来越值钱、货越来越少 | 产出略高于回收，用"回收口"把多余资源吃掉 | 硬约束物资（粮草）+ 软约束货币（铜钱）两套规则 |
| 玩法节奏 | 玩家**不敢花**、倾向囤积，前期极易饿死 | 节奏平顺，回收口决定"富不富" | 粮草紧、铜钱松；战略层紧、战术层松 |
| 资源回收 | 靠"总量减少"被动回收，不可控 | 靠**显式回收口**（耐久/维修/粮耗/税/军饷/维护）主动调节 | 粮草靠消耗与烧毁回收；铜钱靠招募/工钱/税回收 |
| 玩家挫败感 | **高**：断粮已是最强惩罚，再叠"钱买不到东西"= 双重卡死 | 中：失败可归因（没修装备/没运粮），不憋屈 | 低：两套资源互为缓冲，单点失败不致命 |
| 实现成本 | 中：要在每条收入链上做减法，内容一改就饿死玩家 | **低**：只加回收口，收入链不动 | 中：两套口径需要清晰边界（易混） |
| 与本作契合 | 差——本作是剧情驱动、S01~S14 有固定难度曲线 | **好**——难度靠"回收口旋钮"调，不改剧情数值 | 好——粮草是天然的"硬"资源，铜钱天然"软" |

### 4.2 推荐：B 为主、C 为形（即"受控通胀 + 粮草硬约束"）

**结论：不采用纯通缩。** 三条理由：

1. **重复惩罚**：粮草本身就是"持续消耗"，已经是最强的时间压力；再让全经济通缩 = 同一件事罚两次，玩家只会得出"这游戏在劝退"的结论。
2. **不可控**：通缩要求对每条收入链做精确减法。本作有 S01~S14 固定剧情、掉落表、商店——任何一次内容迭代（多给 5 个野果）都会打破平衡，而**通胀侧只需调回收口**，改一个数即可。
3. **玩法冲突**：通缩鼓励"囤积不动"，而本作核心是"出征—战斗—扩张"；囤积最优 = 玩家不出门 = 玩法自毁。

**实施形态 = C 的双轨**：
- **粮草（硬约束）**：只能产出/缴获/截获，不能购买；`storageSpoilPerDay` 让囤积有成本；烧毁是唯一"大额销毁"手段。
- **铜钱（软约束）**：可通胀，用于招募、工钱、维修、税——它是"回收口"的主要载体。
- 两者**不互相兑换**（粮草不可买、铜钱不可换粮），保证"粮道"这件事永远有玩法意义。

### 4.3 替代抓手（如果最终仍想更"紧"）

不做通缩也能达到"资源紧张"的手感，按性价比排序：

| 抓手 | 归属 | 强度 | 说明 |
|---|---|---|---|
| 装备耐久 + 维修费 | 模块 1（**P17，已定稿=是**） | 高 | 最自然的"钱→物"回收口 |
| 箭矢消耗 | 模块 1（**P16，已定稿=是**） | 中 | 弓箭兵长期开销 |
| 粮草日耗 + 仓储损耗 | 模块 9 | 高 | 时间压力主干 |
| 军饷（按日发铜钱） | 模块 3/7 | 中 | 军团常备的"人头税"，鼓励解散/裁军 |
| 建筑维护费 | 模块 7 | 低 | 城池越多越贵，抑制无脑扩张 |
| 税收/民心双向 | 模块 7 | 中 | 高税→民心降→产出降（内生的自我平衡） |

## 5. 模块化设计（可直接进文档正文）

### 5.1 状态机

```
FoodLedger（每军团一条）
  日结时：库存 = 库存 + 自动输送 - 日耗
    ├─ 库存 ≥ 日耗           → 饱食
    ├─ 0 < 库存 < 日耗       → 紧张（-3 士气/日）
    ├─ 库存 = 0 且断粮日 ≤ 3 → 断粮（-8/日 + 禁出兵）
    └─ 库存 = 0 且断粮日 > 3 → 饥溃（-15/日 + 逃散 8%/日 + 战力 ×0.7）

补给到位（任意档 → 饱食）
    ├─ 当日停止逃散
    ├─ 士气 +5/日 回升
    └─ 断粮日计数清零（饥溃再经 1 日缓冲才恢复战力）
```

**断粮 lock**：`断粮/饥溃` 时 `ArmyState.supply.starved = true` → 拒绝 `attack`/`move` 指令（返回 `code: 'armyStarved'`）。
这与 `SceneVehicleRuntime:310` 的载具断粮锁同语义，**不新造概念**。
