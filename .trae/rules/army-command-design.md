# 军团指挥系统设计（Army Command System）

> 状态：设计稿（待评审） · 2026-09-25
> 引出场景：S02 废弃营地剧情重构（张角抉择 + 救援搬运玩法）
> 定位：**通用军团指挥系统**——S02 救援关是首个使用场景，后续战场场景（S03～S13）复用

---

## 1. 背景与目标

S02 现状是"张角召见"过场（interact → 对话 → 接取+传送）。新设计：

1. 主角翻山途中伤饿交加昏倒 → 视角切至张角
2. 黄巾军来报"发现昏倒的人" → 张角二选一：**杀了**（乱世草芥结局）/ **救他**
3. 选"救他"进入**军团指挥玩法**：指挥士兵把晕倒的主角拖回营地 → 主角苏醒 → 衔接原征召线

由此沉淀一套可复用的军团指挥层：保留主角直接操控（ARPG），叠加 RTS 式分队指挥（选择编组、下令移动、行为姿态、工程建造）。

## 2. 核心概念模型

### 2.1 编制与选择（两层分离）

```
Army（军队）                 —— 场景级编制，如"张角亲卫队"
 ├─ Squad（分队）            —— 前军 / 后军 / 左军 / 中军 / 右军
 │   └─ Unit（士兵实体）      —— ECS 实体（复用现有实体管线）
 └─ Commander（武将=玩家自己） —— 不属于任何 Squad，ARPG 直接操控
```

- **选择视图**：武将(自己) / 全军 / 前军 / 后军 / 左军 / 中军 / 右军 —— 是选择过滤器，不是新实体
- **全军** = 全部 Squad；**武将**不编入 Squad、不受 AI 命令（待确认：全军姿态移动时武将是否自动跟随，见 §9）

### 2.2 命令体系（三类）

| 类别 | 命令 | 语义 |
|---|---|---|
| 移动 | 点地下令 | 选中编组向目标点寻路移动（保持分队阵型偏移） |
| **攻击命令**（行为姿态，互斥） | 全速进攻 | 速度上限拉满，向敌推进，接敌即战 |
| | 原地防守 | 驻守当前点，敌进入警戒范围接战 |
| | 缓慢推进 | 保持阵型稳步向前，接敌边战边推 |
| | 稳步撤退 | 向撤退点后撤，边撤边战，保持阵型 |
| | 抢救伤员 | 接近倒地单位执行搬运/救援（S02 核心） |
| | 快速逃命 | 放弃阵型与接战，全速脱离 |
| **特殊命令**（工程/状态） | 鹿角 / 挖坑 / 筑城 / 守城 / 扎营 / 行军（等） | 在目标点生成工程物或改变全军行军状态；清单可扩展 |

### 2.3 S02 搬运玩法（抢救伤员的具体化）

选中 ≥2 名士兵 → 姿态切「抢救伤员」→ 指定晕倒的主角为搬运目标 → 士兵到达后进入**搬运状态**（主角实体被拖动，播放拖拽表现）→ 进入营地触发区 → 主角苏醒过场。

**搬运遇敌规则（已裁定）**：处于搬运状态的士兵遇敌时——
1. 脱离搬运状态，**放下伤员**（伤员留在原地）
2. 自动切入**原地防守**姿态，开始战斗
3. 战斗结束后**不自动恢复搬运**——需玩家重新下达抢救命令（保留指挥决策权）

## 3. 数据模型

- **编制定义**：项目级 `armies`（library 扩展）或场景级定义；Squad 仅存 id + 名称 + 归属单位选择器
- **士兵实体**：复用现有 ECS 实体管线 + 新组件：
  - `SquadMemberComponent`（armyId、squadId、阵型偏移）
  - `CommandStateComponent`（当前 stance、移动目标、搬运目标/状态）
- **存档**：军队/士兵为实体状态，**不入档**（沿用"事实入档、实体重建"惯例）；剧情事实（如"救援完成"）走 state.transaction 入档

## 4. 命令状态机要点

- **命令达成倒计时（已裁定）**：所有命令非瞬时生效——下令后进入执行窗口（一小段倒计时），士兵整队/移动到位后命令才算达成；UI 显示倒计时进度，营造"下令-行军-达成"的指挥节奏
- 姿态互斥，切换即全编组广播；移动下令不改姿态，仅设临时目标点（姿态决定途中行为）
- 接敌判定复用 CombatSystem 阵营判定；警戒范围按姿态参数化（防守 > 推进 > 撤退 > 逃命=0）
- 搬运状态：搬运者速度锁定为慢速、不可接战（或弱反击）；被搬运单位禁用一切输入
- 搬运中断：遇敌即脱离搬运 → 放下伤员 → 切原地防守自动战斗（§2.3），战斗后需玩家重新下令

## 4.1 武将自主权（已裁定）

- **武将完全由玩家控制，不响应任何军团命令**——全军/分队命令只作用于 Squad，保留 ARPG 操作主权
- 军团指挥层与主角操控层并行不互相接管（切换选择到"武将"时即回到 ARPG 操控）

## 5. 三端输入映射

| 操作 | PC | 手柄 | 安卓 |
|---|---|---|---|
| 框选 | **左键按住不放拖拽**（已裁定） | — | — |
| 点选单位 | 左键单击（场景内） | 切换单位键循环：武将→全军→左→中→右→前→后 | 点选 |
| 选择单位/编组（编组按钮） | 编组按钮点选（快捷键待定） | 切换单位键 | 编组按钮点选 |
| 移动下令 | **右键单击**（地面/目标） | —（左摇杆直接控位移） | 点地 |
| 命令选择 | **左键点选**命令面板（HUD 按钮，不与场景点击冲突） | 切换命令键循环 → **A 键确认** | 命令面板点选 |
| 武将自身移动 | WASD（现有） | 左摇杆（现有） | 虚拟摇杆（现有） |

> 左键双职责区分：按下后位移超阈值 = 框选；单击（无位移）= 点选单位。命令面板为 HUD 按钮，左键点击面板不落入场景点击判定。

## 6. 系统集成点

| 系统 | 集成内容 |
|---|---|
| CombatSystem | 士兵阵营标签（友军），敌我判定复用 |
| MovementSystem | 分队跟随（阵型偏移点）、搬运联动（被搬运单位位置由搬运者驱动） |
| 寻路 | 工程物（鹿角/坑）= 动态障碍，寻路网格需支持运行时打洞/恢复 |
| UI | 编组选择条、命令面板（攻击命令页 + 特殊命令页）、框选框渲染、搬运进度提示 |
| 输入 | InputManager 新增编组/命令层（PC 鼠标右键语义在指挥模式下接管；S02 晕倒状态禁用主角交互避免右键冲突） |
| 剧情层 | S02 编排全走任务中心（对话/触发器/quest），军团玩法经 scenario 命令接入 |

## 7. S02 关卡流程编排

1. `sceneEnter` → 旁白对话（翻山、追逃、昏倒；黑屏过渡）
2. 视角切张角 → 黄巾军来报对话（"主公，发现一个昏倒的人"）
3. 张角选项节点：**杀了 / 救他**
4. `dialogueChoice` 分支（沿用 S09 难民分支模式）：
   - `kill` → `ending.command(乱世草芥)`（endings 库新增结局定义）
   - `save` → 生成两名士兵 → 开放指挥玩法 → 任务目标「把伤者拖回营地」→ 到达触发 → 苏醒过场 → 张角征召对话 → 衔接原 acceptSummons 任务线
5. quest/triggers 改造：S02 任务步骤重排；旧 `trg_s02_zhangjiao_summons/accept_summons` 链并入新流程

## 10. 出兵点归属裁定：placement 声明

**推荐：出兵点作为场景 placement 声明，编制数据挂在引用的军队定义上**——理由：

1. **空间归场景**：出兵点本质是"场景里哪里出现什么单位"，空间属性天然属于放置物；策划在场景编辑器里所见即所得地摆放出兵点
2. **复用现有管线**：`spawnPlacements { selector: { group } }` 生成管线已存在（trg_s01_spawn_initial 在用）——出兵点只是新增一种 placement 类别（如 `army-spawn`，携带 armyId/squadId/数量/朝向），生成时注入 SquadMemberComponent 即可，引擎零新概念
3. **编制归定义库**：Army/Squad 编制（兵种、数量构成）放项目级定义（armies），场景 placement 只引用 id——战斗定义（若未来引入）也只引用 armyId，不携带空间数据
4. **分层清晰**：空间数据=placement（场景编辑器编辑）、编制数据=armies 定义（内容库编辑）、生成时机=触发器（剧情编排）——与"场景代码让位给任务"的既有架构一致

battle 定义携带的方案被否原因：空间与编制分离导致策划要跨文件对照编辑、S02 这类非战斗救援场景也被迫造 battle 配置、且无法所见即所得

## 11. M5 简化改造：预设+偶尔覆盖（2026-09-25 裁定）

核心思路一句话：把"实时微操"变成"预设+偶尔覆盖"，武将从"可选单位之一"变成"永远手动的唯一主角"。战斗中玩家 90%+ 时间在 ARPG 控制武将，切军团只是偶尔给一下方向。

### 11.1 已裁定

1. **默认行为=跟随武将（escort）**：军队以阵型偏移跟在武将身后，武将移动他们跟随，武将站定自动结阵接战；全程无视军队也能打。所有指令都是对跟随态的临时覆盖
2. **右键语义化（意图指令）**：选中军后右键点目标即下达语义——
   | 右键点 | 军队行为 | 等价姿态 |
   |---|---|---|
   | 敌人 | 冲向该敌接战 | 全速进攻 |
   | 空地 | 移动到该点并驻守 | 原地防守 |
   | 武将附近 | 向武将靠拢回归跟随 | escort 集结 |
   姿态按钮/QWER 降级为可选高级操作（**热键不占用武将技能键**）
3. **指令后自动回武将**：选中军发完指令（右键意图/姿态）自动清除选择回到武将控制——选择是瞬态的，不存在"滞留在指挥模式"
4. **Tab 循环选择**：全军→前军→左军→中军→右军→后军→全军（不含武将——武将是默认态，不是可选槽）
5. **姿态收敛（终态）**：玩家可见 4 姿态（全速进攻/原地防守/缓慢推进/稳步撤退）；快速逃命→全军紧急按钮（长 CD，后做）；抢救伤员→剧情专用（S02 已实现）
6. **分期**：M5-1 核心手感（1-4）→ M5-2 全局快捷键+选中军边缘高亮 → M5-3 战前 per 军默认姿态+手柄按住 LB 指挥+安卓底部图标栏

### 11.2 与现有实现的关系

- 选择槽/姿态机/命令倒计时/阵型偏移计算全部复用；改动集中在输入层与默认行为
- **rescue（S02 搬运）与建造作业（任务驱动）不受影响**：rescue 姿态单位不接受意图指令（搬运任务优先）
- 命令倒计时保留——它就是"指令有执行过程、非瞬时生效"的表现
- HUD Row2 姿态按钮 M5-1 保留（含 rescue/flee），语义化右键作为主路径叠加；M5-3 再收敛可见项。
