## 1. 抽取器：`src/core/world/WorldMapExtractor.js`

### 1.1 定位

纯函数模块（无 DOM / 无实体 / 不读 Blackboard），输入 `{ project, worldIndex }`，输出**自动层**：
`{ nodes, edges, revision, hash, warnings }`。自动层只在编辑器内存中存在，**永不写回 `worldLogic`**，
运行时不读取（`WorldRouteLayer` 零改动）。

### 1.2 抽取规则（确定性）

数据源：`project.worldMap.regions[].coverage`（terrain + sceneId + row/col + offset + worldWidth/Height）
+ `project.scenes` + `project.variables.cityStates`。

1. **城市节点**（每个 `cityStates[]` 一条）：
   - 场景解析优先级：`cityState.sceneId` → id 前缀 `city.<token>_...` 与 scene.id 忽略大小写匹配
     （`city.s09_guangzong_camp` → `S09`）→ 仍失败则 `warning: citySceneUnresolved` 并跳过。
   - 节点：`{ id: 'city.<token 小写>', kind:'city', name: cityState.name, ref:{id: cityState.id},
     position: 场景格中心 (offset + size/2), ownerFactionId: cityState.factionId, source:'auto' }`。
     id 与既有手写节点一致（如 `city.s09`），便于差异按 id 命中。
2. **过河/过关节点**：
   - 场景格地形为 `yellowRiver` → `kind:'ferry'`，id `ferry.<sceneId 小写>`，name = 场景名；
   - 地形为 `mountain` → `kind:'pass'`，id `pass.<sceneId 小写>`，name = 场景名；
   - 位置 = 该场景格中心，`source:'auto'`。
   - 现内容示例：`s_5_9 山脊隘口`（mountain）→ pass，`s_5_10 涉水浅滩`（yellowRiver）→ ferry。
3. **格网代价**：4 邻接移动；`plain=1`、`forest=2`；`mountain` 只可经过 pass 节点格、
   `yellowRiver` 只可经过 ferry 节点格（其余视为不可通行）；步长按 region 的 `chunkWidth/chunkHeight` 折算 px。
4. **节点对候选**：所有 POI（城市/渡口/关隘）两两求 Dijkstra 格网最短路；丢弃不可达对；
   丢弃路径内部还经过其它 POI 的对（连通性由中间 POI 承担），避免冗余长边。
5. **边的生成**：
   - 对保留下来的候选按路径长度做 **Kruskal 最小生成树**（每连通分量 n-1 条）；
   - 再追加所有「两端格网 4 邻接」的候选边（形成回路，接近手写图的策略选择）；
   - 边：`{ id:'edge.auto.<from>__<to>', from, to, mode, cost, bidirectional:true,
     conditions: crossingNodeId? , source:'auto' }`；
     `cost` = 路径步长折算 px（与手写内容 640/720/1280/3240 同量纲）；
     `mode`：端点含 pass → `mountainPath`，含 ferry → `ferry`，路径以 forest 为主 → `mountainPath`，否则 `road`；
     `conditions.crossingNodeId` = 相邻的 pass/bridge/ferry 端点 id。
6. **revision/hash**：`revision` = 1（每次构建固定，编辑器重抽时自增）；`hash` = 对排序后的
   nodes/edges 规范化 JSON 做 FNV-1a，用于「地图是否变化」判等。
7. **warnings**：`citySceneUnresolved` / `poiDisconnected`（某 POI 无法连到任何其它 POI）/
   `graphDisconnected`（>1 连通分量，附分量节点 id）。

### 1.3 测试：`src/core/world/WorldMapExtractor.test.js`

小型 fixture（3×3 terrainGrid + 3 个场景 + 2 个 cityStates）覆盖：
城市节点位置=格中心；mountain/river 场景分别产 pass/ferry；plain 相邻产 road 边；forest 路径 mode=cost 正确；
城市 id 前缀解析与 `citySceneUnresolved`；总图连通/MST 边数 = 节点数-1+附加回路；hash 稳定（同输入同输出）；
不可达 POI 产 warning。约 10 例。

## 2. 差异模型：`src/core/world/WorldLogicDiff.js`

### 2.1 API（纯函数）

```
buildDiff(autoLayer, manualLogic, { ignoredKeys = [], resolvedKeys = [] })
  -> { categories: { autoOnly:[], manualOnly:[], changed:[] }, counts, total }
adoptAuto(autoLayer, manualLogic, entry)
  -> { ok, logic, code?, removedEdgeIds? }        // 返回新 logic（深拷贝）
keepManual(entry) / ignoreEntry(entry)            // 只产 session 标记，不改数据
adoptAllOfCategory(autoLayer, manualLogic, category, entries)
  -> { ok, logic, applied, skipped:[{key,code}] }
```

### 2.2 匹配键

- 节点：① id 完全相同；② `kind` 相同且位置差 ≤1px；③ 未匹配。
- 边：① id 相同；② 端点经**节点匹配映射**后无序对相同（处理 auto 桥节点改名）；
  ③ 原始 `from/to` 无序对相同；④ 未匹配。
- 差异 key：`node:<manualId||autoId>` / `edge:<manualId||autoId>`；忽略/保留按 key 记。

### 2.3 三类差异与并排字段

| 类别 | 含义 | 展示 |
|---|---|---|
| `autoOnly` | 自动有、人工无 | 自动值摘要（kind/位置/两端/权重）→「人工：—」 |
| `manualOnly` | 人工有、自动无（地图上没了） | 「自动：—」→ 人工值摘要 |
| `changed` | 两边都有但不一致 | 仅列变化字段，逐行 `字段 | 自动值 | 人工值` |

比较字段：
- 节点：`kind`、`position.x`、`position.y`、`ownerFactionId`、`level`、`tollRate`、`ref.id`
  （`name` 只展示不参与判定，避免自动生成的桥名制造噪声）。
- 边：`from`、`to`（连通关系）、`mode`、`cost`（走 `resolveEdgeCost`）、`bidirectional`、
  `conditions.crossingNodeId`、`conditions.factionIds`、`conditions.blockedUntilDay`、`conditions.terrainBlocked`。

### 2.4 四种处理动作

1. **采纳自动**：
   - `autoOnly` 节点 → 追加 clone，写 `source:'manual'`、`autoRevision`；
   - `autoOnly` 边 → 端点未在人工层存在时拒绝（`missingEndpoint`，提示先采纳端点）；
   - `changed` → 把比较字段写入人工条目（保留人工 id），写 `autoRevision`；
   - `manualOnly` → **删除**人工条目（语义：承认地图上已无）；节点删除时级联删除关联边并返回 `removedEdgeIds`。
2. **保留人工**：不改数据，仅加入 session `resolvedKeys`（本次对比不再列出）。
3. **忽略此差异**：加入 session `ignoredKeys`（同上，重抽时清空）。
4. **跳到场景里改对象**：返回 `{ sceneId }`（见 3.4），由 UI 打开场景编辑器。

**全部采纳**：按单一类别执行（`autoOnly` / `manualOnly` / `changed` 三个按钮各自独立），
绝不跨类别；失败项集中在 `skipped` 里展示。

### 2.5 测试：`src/core/world/WorldLogicDiff.test.js`

三类差异各至少 1 例；节点按位置匹配；边经节点映射匹配；changed 仅列变化字段（name 变化不算）；
采纳 autoOnly/changed；采纳 manualOnly 删除节点级联边；missingEndpoint 拒绝；
保留/忽略后从列表消失且不改数据；`adoptAllOfCategory` 不跨类；原 logic 不被原地修改。约 12 例。

### 3.3 存档决策（用户授权范围内自定）

**不持久化 auto 层，也不写 `autoMeta`**：每次打开编辑器按当前地图重算 auto 层，人工层是唯一存档内容。
理由：零体积、无双源、地图变了本来就应该重算；代价是跨会话「忽略/保留」不保留（重抽/重开即清空），
列入「需拍板（不阻塞）」供用户改口径。

### 3.4 「跳到场景改对象」的场景解析

节点：`node.sceneId` → `ref.id` 经 `cityStates` 反查 sceneId（`city.<token>_` 前缀）→
自动节点自带 `sceneId` → 位置最近场景（`ProjectWorldIndex.findScene` 遍历，欧氏距离最小且 ≤1 个 chunk）。
边：取 `from` 节点的场景。解析失败按钮置灰并提示「无法定位场景」。

### 3.5 测试增量：`editor/WorldLogicEditor.test.js`

## 5. 假设与决策

| # | 决策 | 取值 | 理由 |
|---|---|---|---|
| 1 | 抽取来源 | terrainGrid + scene anchor + cityStates（无道路放置物） | 当前地图只有这些可解析信息；不伪造第二套路面数据 |
| 2 | 自动图连通密度 | POI（城/隘/渡）两两格网最短路 + Kruskal MST + 邻接回路 | 确定性、可测、接近手写图的「骨架 + 回路」 |
| 3 | auto 节点 id | 城市沿用 `city.<token>`；隘/渡用 `pass/ferry.<sceneId>` | 最大化与手写 id 命中，减少噪声差异 |
| 4 | 存档 | 只写人工层，不写 auto 层/autoMeta | 零体积、无双源；运行时只读人工层 |
| 5 | 忽略/保留 | session 级，重抽或重开清空 | 不污染存档；如要持久化再单独加 |
| 6 | 删除级联 | 采纳 manualOnly 节点时级联删关联边并回报 | 避免保存时校验失败 |
