## 一、领域层

### 1. `src/systems/world/EncounterResolver.js`（新）

纯数据 + 纯函数，不依赖 DOM / Blackboard / 场景实体。

- 导出 `ENCOUNTER_CHOICES = ['ambush','detour','fight','retreat']`、`DEFAULT_COMBAT`（spec §7 全量默认值）、`class EncounterResolver`。
- 构造注入：`{ combat, rng = Math.random, resolveUnitType, resolveHero, resolveFormation, getCityState, now }`；缺省回退 10/10、command 50、阵法 1.0、城防 0。
- `detect({ state, order, layer, units, day }) → encounter | null`
  - 只对 `order.state==='executing'` 的单位探测；`state.encounterCooldown` 命中当前边则跳过。
  - 三类目标：①`engageRadius`（缺省 120）内敌对 `armyStates` → `kind:'field'`；②路线下一个节点是 `city`/`pass` 且归属敌对 → `kind:'city'|'pass'`；③当前边快照 `hostile` 且 reasons 含 `crossingHeldByEnemy`/`passBlocked` → 对应关隘目标。
  - 产出 `{ id, unitId, kind, edgeId, nodeId, defenderUnitId, defenderFactionId, createdAt, expiresAt, available:{ambush,detour,fight,retreat} }`。
  - `available.ambush`：防守方未警戒（其 `order.type !== 'attack'` 或无目标指向我方）且 `edge.mode ∈ road/bridge/mountainPath`；`available.detour`：`layer.shortestPath(起点, 终点, {avoidEdgeIds:[edgeId]}).ok`。
- `resolve({ encounter, choice, layer, state, units, day }) → outcome`
  - `ambush`：`battle({ambush:true})`，`strategicTicksSpent:1`，路线不变。
  - `detour`：不战、`strategicTicksSpent:0`、`routeRequest:{avoidEdgeIds:[edgeId]}`；无替代路 → `{ok:false, code:'noDetour'}`。
  - `fight`：`battle()`；胜 → 原路继续；败 → `routeRequest:{retreatTo:上一节点}`。
  - `retreat`：不战、耗 1 刻、`moraleDelta:-retreat.moraleCost`、`routeRequest:{retreatTo:上一节点||最近己方节点}`、`cooldown:{edgeId, ticks:retreat.cooldownTicks}`。
- `battle({ attacker, defender, context })`：严格按 §7.1 结构 —— 攻方 `兵力攻击 ×(1+command/heroScale) ×阵法攻 ×士气 ×(1+埋伏) ×堆叠`，守方同构 + 城防/关隘防御 × 地势；`score = atk/def × rng(0.9~1.1)`；`winner = score ≥ winThreshold`（缺省 1）。守方士气 < `routMorale` → 溃败（损兵 ×1.5、士气落 `routMoraleFloor`）。损失比：败方 `defeatLossRatio`、胜方 `victorLossRatio`（按比分劣势放大）。
- `toBattleResult(encounter, battle, day)`：城池/关隘战斗转 `BattleResult` 形状（`resultId/battleId/winnerFactionId/affectedCityId/resourceTransfer/cityDamage/damagedResourceNodeIds/casualties/completedAt`），供 `CityWarSystem` 复用，不另造结算。

### 2. `src/systems/world/PassTariffSystem.js`（新）

- 构造注入：`{ tariff, listPasses, updatePassToll, resolveCityForPass, getDay, onEvent }`。
- `collect({ passId, moverFactionId, ownerFactionId, cargoValue, day })`
  - 同阵营免税；中立/他方 → `tax = cargoValue × (node.tollRate ?? tariff.rate)`（整数向下取整）。
  - **唯一累计点**：`armyStates[passId].supply.toll += tax`（经 `updatePassToll`，不建第二本账）。
- `settle({ day })`
  - 遍历 `kind==='pass'` 且 `supply.toll > 0` 的单位，`resolveCityForPass(passId, ownerFactionId)` 找归属方最近城池。
  - 产出 `transfers:[{passId, cityId, resource, amount}]` 后**清零** `supply.toll`，`lastSettledDay` 幂等（同日重复调用返回空）。
  - 不直接写 `cityStates`——写城由调用方单点执行（防双算），且与城池常规税收账本完全分离（分录事件 `pass.tariffSettled`）。

## 二、接线层

### 3. `src/systems/ArmyOrderSystem.js`（增量）

- `_strategicStep`：探测到遭遇不再直接写 `encounterResolvedAt` 发空事件，改为 `order.pendingEncounter = encounter` + 发 `unit.encounterPending`，本刻不推进（现有 `if (order.pendingEncounter) continue` 生效）。

### 4. `src/core/scene/SceneArmyOrderFlow.js`（增量）

- 构造增 `{ encounterResolver, passTariffSystem, routePlanner, now }`。
- `update`：战略刻后 `_processEncounters()` —— ①玩家可见（地图面板打开 或 单位 `sceneId === 当前场景`）→ `scene.worldMapPanel.showEncounter()` 并暂停；不可见 → 按 `combat.autoPolicy`（缺省 `fight`）立即结算；②`expiresAt` 到点 → 自动 `retreat`（`reason:'timeout'`）。
- `decideEncounter({ unitId, choice, encounterId })`：幂等（`encounterResolvedAt`/pending id 比对）→ `resolver.resolve` → `_applyEncounterOutcome` → 发 `unit.encounterResolved{choice,reason}`；关隘易主发 `pass.captured`；城池/关隘战斗调注入的 `applyBattleResult`（装配器接 `CityWarSystem`）。
- `handleEnterNode({ state, nodeId, node })`：接 `WorldMarchExecutor.onEnterNode`；`node.kind==='pass'` → `passTariffSystem.collect({cargoValue: state.supply?.cargoValue ?? tariff.defaultCargoValue})`。
- 日结：`update` 里比较 `getDay()`，跨日执行 `passTariffSystem.settle()`，把 `transfers` 单点写入 `blackboard.cityStates`（只加 `tariff.resource`，不动其余账簿），发 `pass.tariffSettled`。
- `getPendingEncounter()` 透出给面板。
