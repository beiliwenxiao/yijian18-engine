## 3. Proposed Changes

### 3.1 新增 `src/systems/world/EncounterResolver.test.js`（约 18 例）

自建伪 layer：`{ nodes: Map, getNode/getEdge/getOwner/getSnapshot/shortestPath }`；`combat` 用小数值（`engageRadius:120`、`decisionTimeoutMs:8000`、`decisionHoldTicks:1`、`retreat:{moraleCost:10,cooldownTicks:4}`、`ambushBonus:0.25`）；`rng` 固定序列。

**探测（detect）**

1. 非 `executing` / 无 `factionId` / 已有 `pendingEncounter` → `null`。
2. ① 下一节点为敌占城池 → `kind:'city'`，带 `nodeId`/`edgeId`/`defenderFactionId`，`available.fight/retreat===true`。
3. ① 下一节点为敌占关隘 → `kind:'pass'`。
4. ② `engageRadius` 内敌方单位 → `kind:'field'`；同阵营、`kind==='city'`、`_isDefeated`（`count===0` 或空 `unitIds`+有 `dead`）全部跳过。
5. ③ 当前边 `snapshot.status==='hostile'` → `kind:'pass'`；`conditions.crossingNodeId` 指向 city 节点时为 `'city'`。
6. 冷却：`state.encounterCooldown` 命中 `edgeId` 或 `nodeId` → `null`。

**可用性**

7. `available.ambush`：field + 敌方无 `attack` 令 + 边 `mode` ∈ road/bridge/mountainPath → true；`ferry` → false；无 defender → false。
8. `available.detour`：`shortestPath(avoidEdgeIds)` 有替代 → true；无 → false。

**结算（resolve）**

9. 参数校验：`encounterRequired` / `unknownChoice` / `unitMismatch` / `choiceUnavailable`。
10. 绕道：`strategicTicksSpent===0`、`routeRequest.avoidEdgeIds`、`cooldown===null`；无替代路 → `noDetour`。
11. 撤退：`strategicTicksSpent===1`、`moraleDelta===-10`、`routeRequest.retreatTo===上一节点`、`cooldown.remainingTicks===4`。
12. 战斗胜（field）：`battle.winner==='attacker'`、无 `captured`、无 `battleResult`。
13. 战斗胜（pass/city）：`captured`（kind/nodeId/cityId）+ `battleResult` 形状（`resultId/battleId/winnerFactionId/affectedCityId/resourceTransfer/cityDamage/completedAt`）。
14. 战斗败：`routeRequest.retreatTo` + `cooldown`。
15. `rng` 复现：同种子两次结果一致；`rng=0` → 系数 0.9、`rng→1` → 1.1。
16. 溃败：攻方 `morale < routMorale` → 守方胜。
17. 差异化：`getCityState.buildingLevel` 2 vs 1 → 守方更强；`command` 88 vs 45；`stackLimit` 超员惩罚。
18. 埋伏加成：同种子下 `resolve(ambush)` 的攻方比分 > `resolve(fight)`。

### 3.2 新增 `src/systems/world/PassTariffSystem.test.js`（约 9 例）

用内存 pass 账本（`getPass`/`updatePassToll` 直接改 `supply.toll`）：

1. 同阵营免税：`exempt===true`、`tax===0`、`toll` 不变。
2. 计税：`cargoValue:100` + `rate:0.05` → `tax===5`，累计写入。
3. 缺省口径：无 `rate` 用 `defaultRate`、无 `cargoValue` 用 `defaultCargoValue`。
4. 多笔当日累计。
5. `settle` 跨日：`transfers` 指向归属城池、`total` 汇总、`toll` 清零、发 `pass.tariffSettled`。
6. `settle` 幂等：同 day 二次 → `skipped:'alreadySettled'`，无 transfers。
7. 无归属城池：进 `pending`、累计不清零；补上 `resolveCityForPass` 后次日可结。
8. `serialize/restore` 只带 `lastSettledDay`。
9. `listPasses` 返回非 `kind==='pass'` 时忽略。

### 3.3 新增 `src/core/scene/SceneArmyOrderFlow.encounter.test.js`（约 11 例）

假场景：`{ gameLoader:{blackboard:{get/set}}, worldRouteLayer, worldMapPanel, currentSceneId }`；`ArmyOrderSystem` 用最小军（`factionId`、`position`、`route`、`order.state==='executing'`）。

## 4. Assumptions & Decisions

| # | 决策 | 取值 | 理由 |
|---|---|---|---|
| 1 | 本计划范围 | 只收口 4C | 用户明确「抽取器与差异面板排在 4C 之后作为独立批次」 |
| 2 | 四选后果 | 埋伏：公式 + `ambushBonus`、耗 1 刻、不改路；绕道：不战、不耗刻、改走替代路（无路置灰）；战斗：公式、耗 1 刻、胜续原路/败退上一节点；撤退：不战、耗 1 刻、士气 -10、回退上一节点、4 刻冷却 | spec §6.3；UI hint 与此一致 |
| 3 | 弹窗时机 | 逻辑判定只置 `pendingEncounter` 并暂停本刻；可见（面板开或在该场景）才弹；不可见 `autoPolicy`；超时 8000ms 撤退 | 「地图上撞见时弹，不是判定后直接结算」 |
| 4 | 关税口径 | 累计只写 `armyStates[passId].supply.toll`；跨日 `settle` 产 `transfers`，由场景层单点写 `cityStates[].resources`；不并入城池常规税收 | 用户明确「按日结入城，别和常规税混算」 |
| 5 | 城池易主 / 实时战场 | 4C 只做 `pass.captured` 与 `BattleResult` 适配；城池归属改写与实体展开留 M2/M6 | spec §6.3 与 M2 边界 |
| 6 | UI 载体 | 复用 `WorldMapPanel` canvas 模态，不新增组件 | 既有面板已有输入分发与渲染循环 |
| 7 | 测试风格 | 与源文件同目录、`vitest`、假适配器；不引入新测试依赖 | 仓库既有约定 |
